## Задание 1. Трассировка сортировки выбором (Selection Sort)

**Исходный массив:** `a = {5, 2, 9, 1, 7}` ($n = 5$)

Алгоритм на каждом шаге $i$ ищет индекс минимального элемента в оставшейся неотсортированной части массива (от индекса $i$ до $n - 1$) и меняет его местами с элементом $a[i]$.

### Таблица трассировки:

| Проход $i$ | Индекс минимума | Массив после обмена | Число сравнений на проходе |
| :---: | :---: | :--- | :---: |
| **0** | 3 (значение `1`) | `{1, 2, 9, 5, 7}` | 4 (сравнения с элементами на индексах 1, 2, 3, 4) |
| **1** | 1 (значение `2`) | `{1, 2, 9, 5, 7}` | 3 (сравнения с элементами на индексах 2, 3, 4) |
| **2** | 3 (значение `5`) | `{1, 2, 5, 9, 7}` | 2 (сравнения с элементами на индексах 3, 4) |
| **3** | 4 (значение `7`) | `{1, 2, 5, 7, 9}` | 1 (сравнение с элементом на индексе 4) |

* **Общее число сравнений:**  
  $$4 + 3 + 2 + 1 = 10$$  
  *(Вычисляется по формуле $\frac{n(n - 1)}{2} = \frac{5 \times 4}{2} = 10$)*

## Задание 2. Трассировка сортировки вставками (Insertion Sort)

**Исходный массив:** `a = {4, 3, 2, 1}` ($n = 4$)

Внешний цикл проходит от индекса $i = 1$ до $n - 1$. Элемент `key = a[i]` сравнивается с предшествующими элементами, и те сдвигаются вправо, пока они больше `key`.

### Таблица трассировки:

| $i$ | $key$ | Число сдвигов | Массив после вставки |
| :---: | :---: | :---: | :--- |
| **1** | 3 | 1 (сдвигается 4) | `{3, 4, 2, 1}` |
| **2** | 2 | 2 (сдвигаются 4, затем 3) | `{2, 3, 4, 1}` |
| **3** | 1 | 3 (сдвигаются 4, затем 3, затем 2) | `{1, 2, 3, 4}` |

* **Общее число сдвигов:**  
  $$1 + 2 + 3 = 6$$ сдвигов (наихудший случай для обратно упорядоченного массива).
* **Число сравнений на уже отсортированном массиве из 4 элементов:**  
  **3** сравнения.  
  *(При обходе от $i = 1$ до $3$ на каждом шаге выполняется ровно 1 сравнение: условие $a[j] > key$ сразу ложно, внутренний цикл не выполняется)*.

## Задание 3. Трассировка бинарного поиска

**Массив:** `a = {1, 3, 5, 7, 9, 11, 13}` (длина $n = 7$, индексы $0 \dots 6$).  
Используется целочисленное деление: `mid = (lo + hi) / 2`.

### 1. Поиск элемента $x = 7$:

| Шаг | `lo` | `hi` | `mid` | `a[mid]` | Решение |
| :---: | :---: | :---: | :---: | :---: | :--- |
| **1** | 0 | 6 | 3 | 7 | $a[mid] == x$ ($7 == 7$) $\rightarrow$ элемент найден на индексе **3** |

---

### 2. Поиск элемента $x = 6$:

| Шаг | `lo` | `hi` | `mid` | `a[mid]` | Решение |
| :---: | :---: | :---: | :---: | :---: | :--- |
| **1** | 0 | 6 | 3 | 7 | $a[mid] > 6 \rightarrow hi = mid - 1 = 2$ |
| **2** | 0 | 2 | 1 | 3 | $a[mid] < 6 \rightarrow lo = mid + 1 = 2$ |
| **3** | 2 | 2 | 2 | 5 | $a[mid] < 6 \rightarrow lo = mid + 1 = 3$ |
| **4** | 3 | 2 | — | — | Условие `lo <= hi` нарушено ($3 > 2$), остановка цикла |

* **Чем закончится классический бинарный поиск:**  
  Поиск завершится неудачей — элемент $6$ отсутствует в массиве (алгоритм вернёт `-1` или `false`).
* **Какое значение вернёт `LowerBound(x)`:**  
  Вернёт индекс **`3`**.  
  *Обоснование:* `LowerBound(x)` возвращает индекс первого элемента, который $\ge x$. В данном массиве первым числом, большим либо равным $6$, является $7$, находящееся по индексу `3` (куда в момент завершения указывает переменная `lo`).
