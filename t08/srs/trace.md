# Отчёт по ручной трассировке строк в C#

## Задание 1. Трассировка методов Trim() и Split()

**Исходная строка:**

```
string s = "  Ахметов Ерлан;85 ";

```

1. **Вызов `s.Trim()`:**

   * Метод удаляет все начальные и конечные пробельные символы.

   * Промежуточный результат: `"Ахметов Ерлан;85"`.

2. **Вызов `Split(';')`:**

   * Строка разделяется на подстроки по разделителю `;`.

   * Получается массив `string[]` из двух элементов:

| Индекс | Содержимое элемента | Длина (Length) | Примечание | 
| ----- | ----- | ----- | ----- | 
| `[0]` | `"Ахметов Ерлан"` | **13** | 7 букв фамилии + 1 пробел + 5 букв имени | 
| `[1]` | `"85"` | **2** | 2 цифровых символа | 

## Задание 2. Трассировка int.TryParse для оценок

**Исходная строка:**

```
string line = "Иванов Пётр;70;85;x";

```

После вызова `line.Split(';')` массив содержит 4 элемента:
`["Иванов Пётр", "70", "85", "x"]`.

### Таблица трассировки `int.TryParse`:

| Индекс | Часть (string) | Результат `int.TryParse` | Значение переменной `out` | 
| ----- | ----- | ----- | ----- | 
| `0` | `"Иванов Пётр"` | `false` | `0` | 
| `1` | `"70"` | `true` | `70` | 
| `2` | `"85"` | `true` | `85` | 
| `3` | `"x"` | `false` | `0` | 

### Ответ на вопрос:

* **Что вернёт `TryParseScores` и почему:**

  Метод вернёт **`false`** (неуспешный результат парсинга), поскольку подстрока `"x"` не является валидной числовой записью, и `int.TryParse("x", out ...)` возвращает `false`. При валидации набора оценок возникновение хотя бы одной некорректной записи делает общую операцию разбора неуспешной.

## Задание 3. Сравнение конкатенации string и StringBuilder

Код для анализа:

```
string s = "";
for (int i = 0; i < 4; i++)
    s += i;

```

### Анализ выделения памяти:

1. **Конкатенация строк (`s += i`):**

   * Строки в C# являются **неизменяемыми (immutable)**.

   * При каждой конкатенации старая строка не модифицируется: в куче выделяется память под новый строковый объект `s`.

   * Кроме того, при неявном приведении `i` к строке создаются промежуточные строковые представления `i.ToString()`.

   * Для переменной `s` создаётся **5** строковых объектов: пустая строка и 4 новых состояния на каждом шаге цикла.

2. **Использование `StringBuilder` (`sb.Append(i)`):**

   * Создаётся **1** экземпляр `StringBuilder`.

   * При вызовах `.Append(i)` новые объекты `string` **не создаются**: данные записываются напрямую во внутренний символьный буфер (`char[]`).

   * Строковый объект создаётся лишь однажды в самом конце при вызове `sb.ToString()`.

### Таблица по шагам:

| Шаг / Итерация | Операция `s += i` (значение `s`) | Создано объектов `string` для `s` | Операция `sb.Append(i)` (буфер) | Создано объектов `string` | 
| ----- | ----- | ----- | ----- | ----- | 
| Инициализация | `""` | 1 | `""` (буфер пуст) | 0 | 
| `i = 0` | `"0"` | 2 | `0` | 0 | 
| `i = 1` | `"01"` | 3 | `01` | 0 | 
| `i = 2` | `"012"` | 4 | `012` | 0 | 
| `i = 3` | `"0123"` | 5 | `0123` | 0 | 

## Задание 4. Неизменяемость строк (Immutability)

**Вопрос:** Почему после вызова `s.ToUpper()` без присваивания строка `s` не изменилась?

**Объяснение:**
В C# строки обладают свойством **неизменяемости (immutability)**. Любые строковые методы (включая `ToUpper()`, `ToLower()`, `Trim()`, `Replace()`) не изменяют исходный объект в оперативной памяти. Они возвращают **новую** строку с результатом операции.

Так как результат вызова метода не был сохранён обратно в переменную:

```
s.ToUpper(); // Результат создан в памяти, но никуда не записан и теряется

```

Значение переменной `s` осталось ссылаться на исходную неизменённую строку. Чтобы зафиксировать изменения, необходимо явно присвоить результат:

```
s = s.ToUpper();

```
